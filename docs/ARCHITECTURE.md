# v2 架构 — 双原语组件套件

**依据**：《FunctionComplete 技术组件白皮书 v1.3》§2 组件架构 + §4.3 双原语策略。

## 1. 总览

FCT v2 是五类组件的集合，部署于目标公链（首链 Sepolia）。双原语（门级函数 + DSU）共享容器状态层、压缩状态承诺（CSC）、证明市场与 Ethercoin 清算层。

```

                    │             Ethercoin 清算层          │
                    │  状态根锚定 · 资产映射 · 跨链消息 · 版税  │
                    └────────────┬────────────────────────┘
                                 │ 跨链状态承诺（双向锚定）
      ┌──────────────────────────┼──────────────────────────┐
      │              目标链 FCT 组件集（Sepolia）             │
      │  ┌──────────┐  ┌──────────┐  ┌───────────────────┐  │

      │  │ NAND+LATCH│  │ 哈希/算术 │  │ 提交·验证·质押·罚没 │  │

```

## 2. 组件接口（白皮书 §4.3 双原语策略）

- **FCT 函数接口规范**：函数选择器、输入输出编码、调用语义（借 1.0 API.md）
- **DSU 接口规范**：类别、参数、成本模型、预编译地址（M4 定义）
- **容器 ABI**：资产、引用、权限、AI 服务（M1 定义）
- **证明接口**：重放 / ZK / TEE 证明格式（M3 定义）

## 3. M1 容器组件设计（白皮书 §5.1）

容器是核心状态单元，一个容器 = 一枚容器 NFT 持有的链上账户。

### ContainerNFT（身份层）
- ERC-721（借 1.0 FunctionNFT 手写零依赖模式）
- `mint()` 通过注册表创建 Container 实例并绑定 tokenId
- NFT 转移 → 通知 Container `onNFTTransfer(newAdmin)`，管理员权限联动

### Container（状态层）
| 槽位 | 内容 | 权限 |
|---|---|---|
| 资产 | ETH 余额 + token 余额 | receive 入账；admin 提取 |
| 引用 | DSU 引用集、门级函数引用集（哈希） | admin 增删 |
| 私有状态 | 压缩状态承诺叶子（bytes32，M2 接入 CSC） | admin/执行路径 |
| 管理权限 | admin（默认跟随 NFT 持有者） | NFT 转移联动 |
| AI 服务 | modelCID、inferencePrice、beneficiary | admin 设置；付费推理入账 |

### 核心语义
转移容器 NFT = 容器内资产、服务、管理权、收益全部随之转移（白皮书 §5.1）。

## 4. 借用规则（1.0 保留不动）

| 借用项 | 用途 | 方式 |
|---|---|---|
| fct-library（Python） | 门级函数工具链 | 独立目录引用 |
| FunctionNFT.sol | 门级函数 NFT | M5 集成时扩展（验证证明绑定） |
| Royalty.sol | 版税登记（ETH 结算） | M5/M7 集成 |
| executor（Rust） | 门级执行 + 重放证明 | M4/M6 迁移复用 |
| indexer / frontend | 索引与界面 | 后置集成 |
| Sepolia 基建 | 部署账户/RPC/脚本 | 直接沿用 |
