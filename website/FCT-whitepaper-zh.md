## 摘要

FCT 是由 **Ethercoin 团队维护的链上计算与状态技术组件套件**，为各公链提供可验证、无副作用、只读的链上计算与状态能力。FCT 提供的核心技术正式命名为 **逻辑状态机（Logical State Machine, LSM）**。

**GateLang v2.2** 是 FCT 的**统一可验证计算语言开发工具**。GateLang 以 **NAND 为唯一组合逻辑原语、LATCH 为唯一状态原语**，通过四层抽象将开发者逻辑统一编译为 FCT 兼容产物。其编译产物不是硬件“电路网表”，而是 **可执行逻辑-状态程序 / 逻辑状态机**：组合部分为布尔函数，时序部分为有限状态机，整体可在链上被调用，用于验证、条件求值和状态约束。

FCT 采用**双原语策略**：逻辑原语函数（NAND + LATCH）与领域专用执行单元（DSU）。两者在可计算功能上均可达到图灵完备，并可相互模拟；但在形式化验证粒度、跨链身份、组合语义、证明成本、性能特征上存在显著差异。DSU 不是逻辑原语函数的完全替代品，逻辑原语函数也不是 DSU 的唯一实现方式。FCT 将两者作为互补原语，共享容器状态层、压缩状态承诺、证明市场与 Ethercoin 清算层。

FCT 不定义独立经济系统，不发行代币。涉及 Ethercoin 多链清算层的经济功能，统一使用 **ETHER**。

**FCT 链尚未激活。FCT 未发行任何代币。** 任何声称 FCT 代币、空投、预售、私募、质押、挖矿、映射、兑换、补偿的行为，均与 Ethercoin 团队无关。

## 2. 标准术语：FCT、LSM 与 GateLang

### 2.1 FCT 提供的技术叫：逻辑状态机

**FCT 提供的技术叫逻辑状态机（Logical State Machine, LSM）。**

LSM 的正式定义：

逻辑状态机是一种只读、确定性、可组合的链上计算与状态管理单元。其组合部分由布尔函数定义，时序部分由有限状态机定义，整体以 NAND/LATCH 为最小原语进行结构化编译。LSM 无副作用——不能调用外部合约、不能写入外部状态；其状态转移是原子性的——要么完整执行，要么完全回滚；其行为空间是有限且可形式化验证的——相同输入与状态必然产生相同输出。

### 2.2 GateLang 是语言开发工具

GateLang 是 FCT 的**统一可验证计算语言开发工具**。其编译产物如果运行在链上虚拟机里，更准确的定位是：

**可执行逻辑与状态程序**

它不是硬件意义上的“电路”，而是一套可在链上被调用、用于验证、条件求值和状态约束的逻辑与状态程序。

### 2.3 术语使用原则

在软件/链上环境中，避免使用“电路”“网表”“门级”等硬件术语，除非明确标注为“硬件类比”。推荐术语：

| **抽象层** | **推荐叫法** | **不推荐** |
| :-: | :-: | :-: |
| 数学层 | 布尔函数、状态转移函数、时序逻辑函数 | 逻辑集合 |
| 软件实现层 | 逻辑表达式 DAG、数据流图、有限状态机、状态转移系统 | 电路网表 |
| 链上执行层 | 链上可执行逻辑模块、链上状态机、验证函数 | 门级电路 |
| 元件层 | 逻辑原语集合（NAND、LATCH） | 逻辑集合 |
| 统称 | 可执行逻辑-状态程序、逻辑状态机 | 电路 |

在 CCIP 2.0 语境下：

| **CCIP 2.0 相关对象** | **标准表述** |
| :-: | :-: |
| CCV 验证逻辑 | 验证函数 / 验证状态机 |
| 自定义执行器的条件 | 条件求值程序 / 约束程序 |
| CSC | 状态容器 + 状态转移规则 |
| ACE 合规规则 | 合规约束程序 / 合规状态机 |


## 3. 组件架构

FCT 由五类组件构成：

1. **执行组件**：逻辑原语函数、领域专用执行单元 DSU、双原语策略。

2. **状态组件**：计算容器、压缩状态承诺 CSC、跨链状态承诺。

3. **证明组件**：执行证明、证明市场、无效证明罚没。

4. **清算组件**：目标链适配器、状态根锚定、资产托管与映射、跨链消息。

5. **身份组件**：函数 NFT / 容器 NFT 跨链身份、版税登记。

**GateLang 作为统一语言开发工具**，为上述所有组件提供开发、编译、形式化验证与 AI 辅助能力。

FCT 组件本身不引入代币。若 Ethercoin 多链清算层使用这些组件，其质押、奖励、版税、清算费用均以 ETHER 结算。


## 4. LSM 功能架构

LSM 的功能体系由五个层级构成：

**第一层：计算原语层。** NAND 作为组合逻辑原语，LATCH 作为状态保持原语。两者组合产生：组合部分为布尔函数；时序部分为有限状态机。

**第二层：语言编译层。** GateLang v2.2 提供四层抽象——逻辑原语层、高级语言层、领域 DSL 层、可视化层——统一编译为 FCT 兼容产物。AI 辅助开发必须经 `gatelang-ai-gate` 强制验证，形式化验证充当最终保证者。

**第三层：链上执行层。** LSM 编译产物以**函数 NFT**（可执行逻辑模块）和**容器 NFT**（状态管理凭证）形式部署。函数 NFT 调用是只读的——不消耗 Gas，不产生交易。容器 NFT 封装状态承诺，通过 CSC 压缩状态根。

**第四层：验证与证明层。** LSM 支持三种证明路径：授权可重放、ZK 证明、TEE 证明。证明路径可按资产价值和风险偏好配置。

**第五层：跨链协同层。** LSM 通过适配器接入 EVM、Solana、Cosmos、Move 与比特币 L2。跨链交互不是简单消息传递，而是源链 LSM 与目标链 LSM 之间的状态协同转移。

核心设计原则：**计算分层、状态压缩、权限隔离、载体无关。**


## 5. 执行组件

### 5.1 逻辑原语函数

FCT 提供由 **NAND 纯函数原语**与 **LATCH 状态原语**定义的链上逻辑模块。NAND 逻辑完备，任何可计算函数都可用 NAND 原语结构表达。

- **LATCH 状态**：一个 LATCH 保存一位内部状态，并在每个计算周期更新。通过组合 NAND 与 LATCH，可表达时序逻辑，从而实现图灵完备计算能力。

- **无副作用**：函数不修改任何外部状态，没有调用外部合约的权限。调用陌生人的函数，最坏结果只是返回错误计算结果，无法造成安全伤害。

- **只读可调用**：调用函数是一次只读查询，不消耗 Gas，不产生交易。

- **确定性**：给定相同输入和内部状态，函数总是返回相同输出。

- **可组合**：一个函数可作为子模块被另一个函数调用，组合是结构性的。

- **形式化可验证**：函数是纯逻辑，天然适合模型检查和定理证明。

- **跨链可锚定**：函数 NFT 在目标链注册，可在多链执行与组合。

来源：GateLang L1/L2 编译为 NAND/LATCH 逻辑原语 IR。

### 5.2 领域专用执行单元 DSU

FCT 同时提供 **领域专用执行单元（Domain-Specific Unit, DSU）**：

| **DSU 类别** | **覆盖场景** | **说明** |
| :-: | :-: | :-: |
| 哈希 DSU | Poseidon / Blake3 / SHA-256 | 低成本哈希与承诺 |
| 签名 DSU | EdDSA / BLS / secp256k1 | 支持批量验证 |
| 算术 DSU | 有限域、大整数、椭圆曲线 | 密码学协处理器 |
| 状态机 DSU | 条件分支、循环、跳转 | 提供控制流 |
| ML 推理 DSU | 量化神经网络前向传播 | 可验证 AI 推理核心 |

**图灵完备性**：状态机 DSU + 算术 DSU 组合在理论上图灵完备。  
**只读执行**：DSU 接收输入参数，返回输出，不修改外部状态。状态修改由容器层统一执行。  
**终止性保证**：每个 DSU 有最大执行步数限制，计量单位是类别相关成本模型。

来源：GateLang L3 领域 DSL 编译为 DSU 描述文件；或 L2 高级语言显式调用 DSU。

### 5.3 双原语策略

- **逻辑原语函数**：适合需要极致形式化安全、全量验证、跨链身份一致性、物理上免疫重入与状态操纵的场景。

- **DSU**：适合 AI 推理、密码学运算、高性能批量计算场景。

两者共享容器状态层、证明市场与 Ethercoin 清算层。

#### 5.3.1 计算能力等价性

- 逻辑原语函数：NAND + LATCH 图灵完备。

- DSU：状态机 DSU + 算术 DSU 图灵完备。

- 相互模拟：DSU 可模拟逻辑原语函数；逻辑原语函数可模拟 DSU；混合模式可行。

#### 5.3.2 架构属性差异矩阵

| **属性** | **逻辑原语函数** | **DSU** | **是否自动等价** |
| :-: | :-: | :-: | :-: |
| 无副作用 | 是 | 白皮书规定只读 | 是 |
| 只读调用 | 是 | 是 | 是 |
| 状态修改 | 不能，由容器层统一 | 不能，由容器层统一 | 是 |
| 重入免疫 | 物理上免疫 | 只读约束下免疫 | 是 |
| 确定性 | 逻辑原语结构保证 | 需固定实现与精度 | 需额外约束 |
| 终止性 | LATCH 周期限制 | 最大执行步数限制 | 是 |
| 形式化验证 | 天然适合全量验证 | 模块级验证，较难全量 | **否** |
| 验证粒度 | 逐原语、逐 LATCH | 预编译模块级 | **否** |
| 跨链身份 | NAND 逻辑结构哈希 + 函数 NFT | DSU 版本 + 参数哈希 | **需额外规范** |
| 组合语义 | 结构性引用，组合版税可追溯 | 参数化调用，需登记依赖图 | **需额外规范** |
| 证明成本 | 逐原语证明可能较大 | 类别成本模型，可预测 | 不同 |
| 性能 | 低 | 高 | 不同 |
| 适用场景 | 极致安全、跨链身份、形式化验证 | AI 推理、密码学、高性能批量计算 | 互补 |

#### 5.3.3 混合模式

1. **逻辑原语函数作为身份与验证锚**：函数 NFT 在目标链注册；逻辑原语验证函数验证 DSU 输出证明；状态管理器根据验证结果更新容器。

2. **DSU 作为执行引擎**：接收输入，执行高性能计算；生成重放、ZK 或 TEE 证明；证明提交至证明市场。

3. **证明链**：DSU 执行 → 生成证明 → 逻辑原语验证函数验证证明 → 状态管理器更新容器。跨链时，状态根与证明提交至 Ethercoin 清算层。

4. **版税结算**：逻辑原语函数与 DSU 的依赖关系登记在 Ethercoin 清算层；跨链版税以 ETHER 结算。

#### 5.3.4 选择矩阵

| **场景** | **推荐原语** | **理由** |
| :-: | :-: | :-: |
| 跨链身份锚定 | 逻辑原语函数 | NAND 逻辑结构哈希唯一，适合身份层 |
| 形式化验证 | 逻辑原语函数 | 逐原语可验证，全量证明 |
| 公共函数库 | 逻辑原语函数 | 结构性组合，版税可追溯 |
| RWA 合规检查 | 逻辑原语函数 + DSU | 逻辑原语验证规则，DSU 处理数据 |
| AI 推理 | DSU | ML 推理 DSU 高性能 |
| 密码学运算 | DSU | 算术/签名/哈希 DSU 高效 |
| 批量计算 | DSU | 类别成本模型，可预测 |
| AI Agent 容器 | 混合 | 逻辑原语身份 + DSU 执行 |
| 小额高频调用 | DSU | 低延迟，高吞吐 |
| 极致安全场景 | 逻辑原语函数 | 物理上免疫重入与状态操纵 |


## 6. 状态组件

### 6.1 计算容器

容器是 FCT 的核心状态单元。每个容器是一个链上智能合约账户，持有：

- 资产余额：ETHER、稳定币、其他链资产；

- DSU 引用：该容器允许调用哪些执行单元；

- FCT 函数引用：该容器允许调用哪些逻辑原语函数；

- 私有状态：以压缩状态承诺叶子形式存储；

- 管理权限：容器 Owner，可转移；

- AI 服务：模型 CID、推理价格、收益地址。

容器不同于钱包：钱包属于人，容器属于那枚容器 NFT。容器的主人可以是人，也可以是 AI Agent。**转移容器 NFT，容器内的资产、模型服务、部署的网站、合约管理权以及仍在产生的收益，全部随之转移。**

### 6.2 压缩状态承诺 CSC

FCT 采用**压缩状态承诺（Compressed State Commitment, CSC）**。在 CCIP 2.0 对接语境中，对应标准表述为“状态容器 + 状态转移规则”。

- **数据结构**：二进制 Merkle 树，哈希函数使用 Poseidon 或 Blake3。二进制树分支比十六进制 MPT 短 4 倍，显著降低验证带宽。

- **热状态**：最近一个 epoch 内被访问过的容器，保留完整状态。

- **冷状态**：长期未访问的容器，状态被替换为状态承诺，完整数据由状态切片管理。存储节点仅保留预定义间隔的完整状态快照，中间状态通过历史交易重建。

- **验证**：任何冷状态可通过状态切片 + 向量承诺生成包含证明，无需信任任何链下数据提供者。

### 6.3 状态租金

容器为其占用的压缩状态承诺空间支付**持续租金**，按 epoch 收取。

- 租金定价由状态空间利用率动态调整。

- 不支付租金的容器，其状态被驱逐到冷存储，容器进入休眠，但仍可被唤醒。

- 这解决“状态永久占用但无持续成本”的问题，防止状态无限膨胀。

### 6.4 跨链状态承诺

目标链状态根可锚定到 Ethercoin 清算层，Ethercoin 状态根可回锚目标链。跨链状态承诺使容器状态、函数执行结果、资产映射在目标链与 Ethercoin 之间可验证地同步。


## 7. 证明组件

### 7.1 执行证明

任何节点可以提交**执行证明**，证明它在给定输入下正确执行了某个 DSU 组合或 FCT 函数组合，并产生正确状态转换。执行证明可以是：

- **重放证明**：直接重放执行，适用于小计算量 DSU；

- **ZK 证明**：使用 STARK 或 SNARK 证明执行正确性，适用于大计算量 DSU；

- **TEE 证明**：硬件安全飞地生成远程认证，适用于隐私敏感任务。

### 7.2 证明市场

执行证明由**证明者（Prover）**生成，验证者只需验证证明，无需重放执行。这实现**计算与验证的解耦**——繁重计算在证明者侧完成，链上仅需低成本验证。

- 证明者通过提供证明获得 ETHER 奖励；

- 验证者通过验证证明获得手续费分成；

- 提交无效证明的证明者将被罚没保证金并永久失去资格。

### 7.3 最终性

一旦状态转换证明被超过 2/3 验证者确认，即达到最终性。证明验证是确定性的，最终性时间仅受证明生成与验证时间限制，预计达到**秒级**。

### 7.4 GateLang 形式化验证证明

GateLang 的 `spec` 块与 `gateproof` 生成形式化验证证明，与函数 NFT / 容器 NFT 绑定。调用者可在调用前验证。形式化验证证明与执行证明互补：前者证明逻辑正确性，后者证明执行正确性。


## 8. 清算组件

### 8.1 目标链适配器

Ethercoin 通过 FCT 在目标公链规划部署：

1. 目标链结算合约与轻客户端：验证 Ethercoin 状态根与证明。

2. FCT 计算与状态组件：部署逻辑原语函数、DSU、容器、CSC。

3. 状态根锚定合约：目标链状态根提交至 Ethercoin，Ethercoin 状态根回锚目标链。

4. 资产托管与映射合约：目标链锁定资产，Ethercoin 清算层映射/铸造，提款时销毁并解锁。

5. 跨链消息与版税清算模块：跨链函数调用、容器转移、版税结算。

### 8.2 清算流程

1. 用户在目标链锁定资产或提交状态转换。

2. 目标链 FCT 组件执行函数/DSU，生成证明。

3. 状态根与证明提交至 Ethercoin 清算层。

4. Ethercoin 验证证明，更新全局清算状态。

5. Ethercoin 上映射资产铸造/销毁，或触发目标链释放。

6. Ethercoin 状态根回锚目标链。

结果：Ethercoin 规划以目标公链的 L2/侧链形态运行，提供类似跨链桥的清算功能，但使用证明市场与容器状态，降低传统桥风险。

### 8.3 与跨链桥的区别

| **维度** | **传统跨链桥** | **Ethercoin FCT 清算** |
| :-: | :-: | :-: |
| 信任假设 | 多签或外部验证者 | 证明市场 + 目标链轻客户端 |
| 状态验证 | 依赖桥方 | 状态根双向锚定 + 可验证证明 |
| 计算能力 | 仅资产转移 | 可验证计算 + 容器状态 + 资产 |
| 失败模式 | 单点故障、多签作恶 | 证明罚没、挑战期、限额、保险基金 |
| 代币 | 桥方代币 | ETHER 统一结算，FCT 无代币 |

### 8.4 安全机制

- **多证明**：TEE、ZK、Optimistic 三路径可选。

- **挑战期**：大额提款延迟与分批释放。

- **限额**：单笔与周期限额控制风险敞口。

- **保险基金**：协议金库部分资金用于极端情况赔付。

- **去中心化证明者**：无单一多签，防止单点作恶。

- **目标链重组防护**：轻客户端验证 + 多证明 + 挑战期，防止目标链重组导致清算错误。

- 跨链调用产生的版税以 ETHER 结算。

- FCT 不发行代币，版税不涉及 FCT 代币。

### 9.3 版税适配

- **以太坊结算层**：EIP-1559 风格，优先费进入执行节点奖励池，版税从调用费中扣除。

- **Robinhood Chain**：排序先到先得，优先费不再用于加速交易，而完全转化为函数创作者的版税来源。

- **Solana**：Metaplex Core Royalties Plugin 默认强制执行创作者版税，支持最多 5 个创作者分成，并可通过 Allowlist/Denylist 控制市场程序。状态管理器在函数调用时触发 SPL Token 转账。


## 10. 多链部署模式

以下均为规划，**不代表 FCT 链已激活或已主网运行**。

### 10.1 以太坊

- 规划部署身份锚定、函数 NFT 标准、状态根验证模板。

- 以太坊作为信任根源与跨链身份层之一。

- Ethercoin 规划作为以太坊的 L2/侧链形态，提供计算与清算扩展。

### 10.2 Robinhood Chain

- 规划移植 EVM 合约：函数 NFT 合约、版税分配合约、结算合约验证逻辑。

- 适配约 100ms 出块，近实时状态更新。

- 优先费转化为创作者版税来源。

- 面向 RWA：股息计算函数、合规检查函数等可免信任组合。

### 10.3 Solana

- 规划将函数编译为 BPF 只读纯计算程序：只读账户、不执行 CPI、不标记可写。

- 状态由独立 PDA 与状态管理器更新。

- NAND 逻辑原语结构编译为 Noir 电路，Groth16 证明通过 alt\_bn128 syscalls 验证。

- 通过 Rome Protocol 与 EVM 生态共享状态、原子调用。

- 函数 NFT 使用 Metaplex Core，版税插件适配。

- 利用 Sealevel 并行执行，释放免信任组合的并行价值。

### 10.4 其他公链

- Cosmos、Move 系、比特币 L2 等通过 FCT 适配器接入。

- 统一以 Ethercoin 为清算层，目标链为安全锚定源之一。

### 10.5 渐进式解耦

多链部署的关键风险控制原则是：每一步都不依赖前一步“完成”，而是**独立可验证**。

- 以太坊上的函数 NFT 在 Robinhood Chain 迁移之前就已经是有效的。

- Robinhood Chain 上的函数执行在 Solana 程序部署之前就已经可以独立运行。

- Solana 上的 BPF 纯计算程序和 Groth16 验证可独立于 Rome 桥接进行测试。

- Rome Protocol 集成失败不会使 Robinhood Chain 或以太坊上的成果作废。

- 某一步遇到技术障碍时，前一步成果不会作废。

**注意：以上为架构规划。FCT 链尚未激活。FCT 未发行任何代币。**

## 12. 安全模型

### 12.1 执行安全

- 逻辑原语函数无副作用，免疫重入与状态操纵。

- DSU 只读，状态由容器层统一修改。

- 状态管理器守门：函数只提供“建议新状态”，状态管理器验证业务规则后写入。

- 证明市场：TEE、ZK、Optimistic 三路径可选。

- 无效证明罚没 ETHER 保证金。

### 12.2 状态安全

- 容器状态由 CSC 承诺，冷热分离。

- 状态租金防止状态无限膨胀。

- 跨链状态承诺双向锚定，防止状态不一致。

### 12.3 清算安全

- 多证明、挑战期、限额、保险基金、去中心化证明者。

- 目标链轻客户端验证 Ethercoin 状态根。

- 异常触发挑战与罚没。

- 无单一多签；大额提款延迟与分批释放。

### 12.4 历史安全事件针对性分析

| **攻击类型** | **代表事件** | **攻击利用的“灵活性”** | **LSM 的针对性机制** |
| :-: | :-: | :-: | :-: |
| 验证者私钥泄露 | Ronin, Wormhole | 身份信任可被多数签名覆盖 | 逻辑验证取代身份信任，签名无法绕过状态转移规则 |
| 签名/编码缺陷 | Wormhole | 运行时对模糊输入的“宽容”处理 | 确定性布尔函数，输入输出穷举可验证 |
| 重入攻击 | The DAO | 外部调用导致状态不一致窗口 | 无副作用、只读调用，状态转移原子化 |
| 预言机操纵 | Bonzo Lend | 单一数据源可被伪造 | 数据来源结构性约束 + 客户端可独立复现 |
| 治理/配置失误 | Kelp DAO | 人为配置可被误导或疏忽 | 操作规范硬编码为状态机前置条件 |
| 跨链最终性违反 | Nomad, Ronin | 时间窗口估计的粗略性 | 时间等待转化为状态条件，最终性编码到逻辑中 |

### 12.5 防作弊矩阵

| **攻击类型** | **防御措施** | **技术实现** |
| :-: | :-: | :-: |
| Sybil 攻击 | 高质押 + 声誉积累 | 新节点任务配额 = f(质押, 声誉历史) |
| 虚假计算报告 | 分层验证 | 乐观锚点 / ZK 证明 / TEE 认证 |
| 模型冒名 | 权重哈希白名单 + 中间激活检查 | `modelCID` 必须在链上白名单；锚点检查捕获不同模型层输出分布 |
| 买卖合谋 | 随机验证者选择 + 验证者自身质押罚没 | VRF 选择验证者；验证者质押规模等于矿工 |
| 训练梯度伪造 | 检查点评估 + 优化器状态哈希 | 验证者运行测试集推理；无指标提升则罚没 |
| 蒸馏数据伪造 | 独立路径复现 + 代理签名 | 验证者通过不同代理路径获取答案，比较语义相似度 |
| 蒸馏代理篡改 | 路径签名 + 异常检测 | 每跳签名形成哈希链；验证结果差异超阈值则追溯并惩罚 |
| 矿工报价合谋 | VRF 随机选择矿工 | 报价历史上链，异常报价触发声誉惩罚 |
| 用户虚假高价锁定 | 任务创建锁定全额 ETHER | 挑战失败则罚没质押金 |
| 差额操纵 | 链上合约自动计算差额 | 参数由 DAO 治理，有上下界与时间延迟 |
| 跨链状态伪造 | 轻客户端 + 多证明 + 挑战期 | 目标链轻客户端验证 Ethercoin 状态根；异常触发挑战与罚没 |
| 跨链桥单点 | 去中心化证明者 + 限额 + 保险基金 | 无单一多签；大额提款延迟与分批释放 |

### 12.6 双原语安全边界

- **逻辑原语函数安全边界**：NAND + LATCH 纯逻辑，无副作用，物理上免疫重入与状态操纵。

- **DSU 安全边界**：只读执行，状态由容器层统一修改；需固定实现、精度与终止性。

- **混合模式安全边界**：DSU 输出由逻辑原语验证函数验证，状态管理器守门；证明链完整可追溯。

- **共享安全机制**：证明市场、挑战期、限额、保险基金、去中心化证明者。

### 12.7 AI 辅助开发安全

- AI 生成代码必须通过 `gatelang-ai-gate` 强制验证。

- AI 优化必须提供等价性证明。

- AI 生成的 `spec` 必须通过 `gateproof` 验证。

- AI 模块失败必须是安全的（fail-safe），不得产生未验证的代码。


## 13. 创作者经济

FCT 组件本身不引入代币。函数创作者、DSU 创作者、容器设计者通过 **ETHER** 获得版税。

### 13.1 收入来源

- **函数调用版税**：函数被交易或 DApp 调用时，调用者支付费用中一部分作为版税分配给创作者。

- **组合版税**：函数被另一个函数引用或组合时，原始函数创作者也获得版税。

- **PoC 挖矿奖励**：协议设立函数挖矿池，对高质量、高调用量函数给予 ETHER 奖励。

- **治理与审计奖励**：ETHER 持有者可参与治理，社区成员可审计函数，成功报告获得赏金和声誉。

- **赏金与竞赛**：协议和生态基金定期发布函数设计赏金任务与竞赛。

### 13.2 跨链版税

- 跨链调用产生的版税由 Ethercoin 清算层统一结算。

- Robinhood Chain 上优先费转化为创作者版税来源。

- Solana 上通过 Metaplex Core Royalties Plugin 和状态管理器触发 SPL Token 转账。

- **FCT 不发行代币，版税不涉及 FCT 代币。**

### 13.3 公共函数库与形式化验证协作

- 社区共同维护公共函数库：加法器、比较器、移位器、哈希函数、签名验证等。

- 任何创作者都可提交函数，经社区审计和形式化验证后标记为“已验证”。

- 已验证函数获得更高调用优先级和挖矿权重。

- 社区可组织验证协作，由专业审计者使用模型检查、定理证明等工具对函数形式化验证。

- 验证证明与函数 NFT 绑定，调用者可在调用前验证。

- 验证者获得 ETHER 奖励和声誉。

### 13.4 经济飞轮

1. 优质函数吸引调用。

2. 调用产生版税。

3. 更多函数丰富生态。

4. 更多 DApp 带来更多调用。

5. 收入吸引更多创作者。

该飞轮由 Ethercoin 生态内生经济激励驱动，不依赖外部补贴。


## 14. LSM 在区块链的应用前景

如果预言机解决了“链上如何获取可信外部数据”，并催生了 Chainlink；那么**逻辑状态机（LSM）**解决的是“链上如何以可验证、确定性、无副作用的方式执行逻辑和管理状态”。它可能催生的不是另一个数据网络，而是一个**可验证逻辑与状态层**。

| **项目类型** | **类比** | **核心价值** |
| :-: | :-: | :-: |
| 逻辑状态机网络 | Chainlink | 去中心化可验证逻辑与状态服务 |
| LSM-CCV 市场 | 跨链验证者市场 | 形式化验证的跨链安全层 |
| 合规状态机网络 | 合规预言机 | 监管可验证的合规逻辑 |
| 函数 NFT 市场 | App Store | 逻辑模块经济 |
| 跨链状态协同协议 | 状态桥 | 状态一致性而非仅资产转移 |
| 意图求解器网络 | 求解器网络 | 条件驱动的自动执行 |
| 可验证 AI 代理网络 | AI 安全层 | AI 行为约束与审计 |
| 状态租金协议 | 状态管理中间件 | 状态压缩与成本计量 |
| 治理状态机 | DAO 安全层 | 治理规则硬约束 |
| 形式化验证即服务 | 审计自动化 | 降低形式化验证门槛 |

### 14.1 逻辑状态机网络

节点运行 GateLang 编译的逻辑状态机，为 dApp 提供只读验证、条件求值、合规检查和状态承诺验证服务。节点按验证复杂度获得代币激励，发行方按需调用。与 CCIP 2.0 结合，节点可作为外部 CCV，为跨链消息提供形式化验证。

### 14.2 跨链验证者市场

针对 Ronin、Wormhole、Kelp 等攻击。在 CCIP 2.0 中，发行方可叠加外部 CCV。LSM-CCV 市场允许第三方发布经过形式化验证的跨链验证状态机，发行方按资产价值选择不同安全层级的验证程序。

### 14.3 合规状态机网络

将 KYC/AML、制裁筛查、交易限额、白名单规则编译为逻辑状态机，与 CCIP 2.0 的 ACE 集成。监管方和审计方可独立验证合规状态机的转移规则，无需信任发行方的 Solidity 实现。

### 14.4 函数 NFT / 容器 NFT 应用市场

开发者将验证函数、金融策略、游戏规则、保险理赔条件编译为 LSM，以函数 NFT 形式发布。容器 NFT 封装状态管理权与资产。其他项目可引用、组合、授权这些模块。这类似“链上逻辑的 App Store”。

### 14.5 跨链状态协同协议

利用 CSC 封装状态承诺，源链 LSM 输出状态根，目标链 LSM 验证并执行对应状态转移。适用于跨链游戏、供应链、身份系统、DAO 治理状态同步。

### 14.6 意图求解器网络

用户表达意图，LSM 定义条件，求解器竞争执行。意图满足条件编译为逻辑状态机，求解器提交执行方案，验证者用 LSM 验证方案是否满足条件。可用于跨链交换、限价单、自动再平衡、保险自动理赔。

### 14.7 可验证 AI 代理网络

AI 是加速器，形式化验证是保证者。GateLang 的 `gatelang-ai-gate` 强制 AI 辅助开发经过验证。LSM 可作为 AI 代理行为的约束层：AI 提出的操作必须满足预设状态机规则，才能被执行器执行。

### 14.8 状态租金与状态压缩协议

CSC + 历史默克尔树 + 扩展默克尔树。LSM 可只验证状态根，不展开完整状态。项目可提供状态压缩、状态租金计量、状态清理服务，降低全节点存储负担和状态膨胀。

### 14.9 治理与权限状态机

将治理规则、多签门槛、时间锁、权限转移编译为 LSM。高权限操作必须满足预设状态转移序列，而非依赖人为配置。Kelp DAO 的 1-of-1 配置在 LSM 架构下无法通过初始化验证。

### 14.10 形式化验证即服务

项目可提供从 Solidity、DSL 或自然语言到 GateLang 的编译器，自动生成逻辑状态机，并输出形式化验证报告。这降低形式化验证门槛，可服务于 DeFi、保险、供应链等需要高保证的场景。

**最可能诞生的是“逻辑状态机网络”**——一个与 Chainlink 并列的基础设施层。Chainlink 提供“数据可用性”，LSM 提供“逻辑与状态的可验证性”。两者结合 CCIP 2.0，可形成 **“数据 + 逻辑 + 状态”** 的模块化区块链栈。
