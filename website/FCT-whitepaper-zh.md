## 摘要

FCT 是由 **Ethercoin 团队维护的链上计算与状态技术组件套件**，为各公链提供可验证、无副作用、只读的链上计算与状态能力。

**FCT 链尚未激活。FCT 未发行任何代币。** FCT 目前处于技术规范、组件开发与测试阶段。任何声称 FCT 代币、空投、预售、私募、质押、挖矿、映射、兑换、补偿的行为，均与 Ethercoin 团队无关。

FCT 的目标是：让目标公链通过部署 FCT 组件，获得门级链上函数、领域专用执行单元、计算容器、压缩状态承诺、执行证明与证明市场、跨链清算适配器。Ethercoin 规划通过 FCT 在目标公链部署适配器，以该公链的 **L2 或侧链**形态运行，提供类似跨链桥但更可验证的清算功能。

FCT 采用**双原语策略**：门级链上函数（NAND + LATCH）与领域专用执行单元（DSU）。两者在**可计算功能**上均可达到图灵完备，并可相互模拟；但在**形式化验证粒度、跨链身份、组合语义、证明成本、性能特征**上存在显著差异。DSU 不是门级函数的完全替代品，门级函数也不是 DSU 的唯一实现方式。FCT 将两者作为互补原语，共享容器状态层、压缩状态承诺、证明市场与 Ethercoin 清算层。

FCT 不定义独立经济系统，不发行代币。涉及 Ethercoin 多链清算层的经济功能，统一使用 **ETHER**。

FCT 独立网站为 \*\*[http://functioncomplete.com/\*\*](http://functioncomplete.com/)。该网站用于发布 FCT 技术文档、组件规范与后续升级说明。网站当前内容尚未同步更新，后续将根据本白皮书升级。在网站完成升级前，请以本白皮书及 Ethercoin 官方渠道发布的信息为准。

## 2. 组件架构

FCT 由五类组件构成：

1. **执行组件**：门级链上函数、领域专用执行单元 DSU、双原语策略。

2. **状态组件**：计算容器、压缩状态承诺 CSC、跨链状态承诺。

3. **证明组件**：执行证明、证明市场、无效证明罚没。

4. **清算组件**：目标链适配器、状态根锚定、资产托管与映射、跨链消息。

## 3. 执行组件

### 3.1 门级链上函数

FCT 提供由 **NAND 门网络**定义的门级链上函数。NAND 门逻辑完备，任何可计算函数都可用 NAND 门网络表达。

- **LATCH 状态**：一个 LATCH 保存一位内部状态，并在每个计算周期更新。通过组合 NAND 门和 LATCH，函数可表达时序逻辑，从而实现图灵完备计算能力。

- **无副作用**：函数不修改任何外部状态，没有调用外部合约的权限。调用陌生人的函数，最坏结果只是返回错误计算结果，无法造成安全伤害。

- **只读可调用**：调用函数是一次只读查询，不消耗 Gas，不产生交易。

- **确定性**：给定相同输入和内部状态，函数总是返回相同输出。

- **可组合**：一个函数可作为子模块被另一个函数调用，组合是结构性的。

- **形式化可验证**：函数是纯逻辑，天然适合模型检查和定理证明。

- **跨链可锚定**：函数 NFT 在目标链注册，可在多链执行与组合。

### 3.2 领域专用执行单元 DSU

FCT 同时提供**领域专用执行单元（Domain-Specific Unit, DSU）**，作为高性能、AI 原生的执行原语：

| DSU 类别 | 覆盖场景 | 说明 |
| - | - | - |
| **哈希 DSU** | Poseidon / Blake3 / SHA-256 | 低成本哈希与承诺 |
| **签名 DSU** | EdDSA / BLS / secp256k1 | 支持批量验证 |
| **算术 DSU** | 有限域、大整数、椭圆曲线 | 密码学协处理器 |
| **状态机 DSU** | 条件分支、循环、跳转 | 提供控制流 |
| **ML 推理 DSU** | 量化神经网络前向传播 | 可验证 AI 推理核心 |


**图灵完备性**：状态机 DSU + 算术 DSU 的组合在理论上是图灵完备的。状态机 DSU 提供控制流，算术 DSU 提供数据处理，ML 推理 DSU 提供 AI 专用计算。

**只读执行**：DSU 接收输入参数，返回输出，不修改外部状态。状态修改由容器层根据输出统一执行。被调用的 DSU 无法修改调用者的状态。

**终止性保证**：每个 DSU 有最大执行步数限制，计量单位是类别相关的成本模型，而非统一操作码计数。

### 3.3 双原语策略概述

目标公链可按需选择门级函数或 DSU：

- **门级函数**：适合需要极致形式化安全、全量验证、跨链身份一致性、物理上免疫重入与状态操纵的场景。

- **DSU**：适合 AI 推理、密码学运算、高性能批量计算场景。

两者共享容器状态层、证明市场与 Ethercoin 清算层。

### 3.4 双原语策略详细技术分析

#### 3.4.1 问题定义

FCT 白皮书提出双原语策略：目标公链可按需选择**门级链上函数**或**领域专用执行单元 DSU**。一个关键问题是：

> **DSU 是否实现门级函数的所有功能？**

答案是分层的：

- **在可计算功能上**：DSU 可以实现门级函数的所有可计算功能。

- **在架构属性上**：DSU 不自动等价于门级函数。

- **在工程实践中**：两者互补，而非替代。

#### 3.4.2 计算能力等价性

**门级函数的完备性基础**：

- NAND 门逻辑完备，可构建任意组合逻辑电路。

- LATCH 保存内部状态，使函数可表达时序逻辑。

- NAND + LATCH 组合是图灵完备的。

**DSU 的完备性基础**：

- 状态机 DSU 提供条件分支、循环、跳转等控制流。

- 算术 DSU 提供有限域、大整数、椭圆曲线等数据处理。

- 状态机 DSU + 算术 DSU 组合是图灵完备的。

- ML 推理 DSU 是专用加速单元，不单独承担完备性。

**相互模拟关系**：

| 模拟方向 | 可行性 | 代价 |
| - | - | - |
| DSU 模拟门级函数 | 可行 | 需用状态机 DSU + 算术 DSU 实现 NAND 与 LATCH 语义，性能高但需额外规范 |
| 门级函数模拟 DSU | 可行 | 需用 NAND 网络实现哈希、签名、算术、ML 推理，功能可达但性能极低 |
| 混合模式 | 可行 | 门级函数负责身份与验证锚定，DSU 负责高性能执行 |


**结论**：在“可计算功能”维度，DSU 与门级函数等价。两者均可表达任意可计算函数。但等价性仅限于计算能力，不延伸至架构属性。

#### 3.4.3 架构属性差异矩阵

| 属性 | 门级函数 | DSU | 是否自动等价 |
| - | - | - | - |
| 无副作用 | 是 | 白皮书规定只读 | 是 |
| 只读调用 | 是 | 是 | 是 |
| 状态修改 | 不能，由容器层统一 | 不能，由容器层统一 | 是 |
| 重入免疫 | 物理上免疫 | 只读约束下免疫 | 是 |
| 确定性 | 门网络保证 | 需固定实现与精度 | 需额外约束 |
| 终止性 | LATCH 周期限制 | 最大执行步数限制 | 是 |
| 形式化验证 | 天然适合全量验证 | 模块级验证，较难全量 | **否** |
| 验证粒度 | 逐门、逐 LATCH | 预编译模块级 | **否** |
| 跨链身份 | NAND 网络哈希 + 函数 NFT | DSU 版本 + 参数哈希 | **需额外规范** |
| 组合语义 | 结构性引用，组合版税可追溯 | 参数化调用，需登记依赖图 | **需额外规范** |
| 证明成本 | 逐门证明可能较大 | 类别成本模型，可预测 | 不同 |
| 性能 | 低 | 高 | 不同 |
| 适用场景 | 极致安全、跨链身份、形式化验证 | AI 推理、密码学、高性能批量计算 | 互补 |


#### 3.4.4 形式化验证差异

**门级函数**：

- 每个 NAND 门和 LATCH 可独立形式化建模。

- 函数整体可导出为模型检查或定理证明目标。

- 验证证明可与函数 NFT 绑定，调用者可在调用前验证。

- 适合全量验证公共函数库。

**DSU**：

- DSU 是预编译模块，形式化验证需针对实现代码与规范。

- 验证粒度是模块级，而非逐门级。

- 需额外提供形式化规范、边界条件证明、成本模型证明。

- 高性能实现可能引入非确定性（如浮点、GPU 并行），需固定精度与确定性内核。

**混合模式**：

- 门级函数可作为“验证锚”，验证 DSU 输出的正确性。

- DSU 可作为“执行引擎”，提供高性能计算。

- 证明链：DSU 执行 → 生成证明 → 门级验证函数验证证明 → 状态管理器更新容器。

#### 3.4.5 跨链身份与组合语义

**门级函数**：

- 函数 NFT 包含 NAND 门网络完整描述。

- 网络哈希天然唯一，适合作为跨链身份。

- 组合关系是结构性的：函数 A 引用函数 B，依赖图可追溯。

- 组合版税可按引用关系自动分配。

**DSU**：

- DSU 身份由版本、参数、模型 CID、成本模型哈希共同定义。

- 需在 Ethercoin 清算层与目标链登记。

- 组合关系需显式登记依赖图。

- 组合版税需按依赖图分配。

**结论**：DSU 要完全实现门级函数的跨链身份与组合语义，需要额外登记、版本管理与证明绑定。

#### 3.4.6 确定性与终止性

**门级函数**：

- 确定性由 NAND 门网络保证。

- 终止性由 LATCH 周期限制保证。

- 无浮点、无并行、无硬件依赖。

**DSU**：

- 需强制固定精度、确定性内核、确定性随机源。

- ML 推理 DSU 需固定模型版本、权重哈希、量化参数。

- 终止性由最大执行步数与类别成本模型保证。

- GPU 并行需保证归约顺序确定性。

#### 3.4.7 证明成本与性能

| 维度 | 门级函数 | DSU |
| - | - | - |
| 执行速度 | 低 | 高 |
| 证明生成 | 逐门证明可能较大 | 类别成本模型，可预测 |
| 链上验证 | 逐门验证可能较贵 | 预编译验证，成本可控 |
| 适合规模 | 小规模、高安全 | 大规模、高性能 |
| 典型场景 | 跨链身份锚定、形式化验证、合规检查 | AI 推理、密码学运算、批量计算 |
| ZK 路径 | Noir/Groth16 可编译 | 类别专用电路 |
| TEE 路径 | 适合小函数 | 适合大模型推理 |
| Optimistic 路径 | 适合公共函数库 | 适合高频调用 |


#### 3.4.8 共享层

双原语共享以下层：

- **容器状态层**：资产、DSU 引用、FCT 函数引用、私有状态、管理权限、AI 服务。

- **压缩状态承诺 CSC**：二进制 Merkle 树，冷热分离，状态租金。

- **证明市场**：重放、ZK、TEE 三路径，证明者质押与罚没。

- **Ethercoin 清算层**：状态根锚定、资产映射、跨链消息、版税结算。

- **治理**：ETHER 持有者参与参数治理。

- **经济媒介**：ETHER 是唯一代币，FCT 无独立代币。

#### 3.4.9 选择矩阵

| 场景 | 推荐原语 | 理由 |
| - | - | - |
| 跨链身份锚定 | 门级函数 | NAND 网络哈希唯一，适合身份层 |
| 形式化验证 | 门级函数 | 逐门可验证，全量证明 |
| 公共函数库 | 门级函数 | 结构性组合，版税可追溯 |
| RWA 合规检查 | 门级函数 + DSU | 门级验证规则，DSU 处理数据 |
| AI 推理 | DSU | ML 推理 DSU 高性能 |
| 密码学运算 | DSU | 算术/签名/哈希 DSU 高效 |
| 批量计算 | DSU | 类别成本模型，可预测 |
| AI Agent 容器 | 混合 | 门级身份 + DSU 执行 |
| 小额高频调用 | DSU | 低延迟，高吞吐 |
| 极致安全场景 | 门级函数 | 物理上免疫重入与状态操纵 |


#### 3.4.10 混合模式

混合模式是双原语策略的核心工程实践：

1. **门级函数作为身份与验证锚**：

   - 函数 NFT 在目标链注册。

   - 门级验证函数验证 DSU 输出证明。

   - 状态管理器根据验证结果更新容器。

2. **DSU 作为执行引擎**：

   - 接收输入，执行高性能计算。

   - 生成重放、ZK 或 TEE 证明。

   - 证明提交至证明市场。

3. **证明链**：

   - DSU 执行 → 生成证明 → 门级验证函数验证证明 → 状态管理器更新容器。

   - 跨链时，状态根与证明提交至 Ethercoin 清算层。

4. **版税结算**：

   - 门级函数与 DSU 的依赖关系登记在 Ethercoin 清算层。

   - 跨链版税以 ETHER 结算。

#### 3.4.11 对目标公链的接口

目标公链可部署：

- **仅 DSU**：追求高性能与 AI 原生。

- **仅门级函数**：追求极致安全与形式化验证。

- **双原语**：混合模式，门级锚定身份，DSU 执行。

统一接口：

- **FCT 函数接口规范**：函数选择器、输入输出编码、调用语义。

- **DSU 接口规范**：类别、参数、成本模型、预编译地址。

- **容器 ABI**：资产、引用、权限、AI 服务。

- **证明接口**：重放、ZK、TEE 证明格式。

#### 3.4.12 对开发计划影响

双原语策略对 FCT 开发计划的影响：

- **阶段 0**：规范需同时定义门级函数接口与 DSU 接口。

- **阶段 1**：原型需实现门级函数引擎与 DSU 运行时。

- **阶段 2**：开发者工具需支持原语选择与混合模式。

- **阶段 3**：安全审计需覆盖双原语与混合证明链。

- **阶段 4**：多链适配器需支持目标链按需选择原语。

- **阶段 5**：生态需支持门级函数与 DSU 的组合、版税与治理。

#### 3.4.13 结论

**DSU 在“可计算功能”上可以实现门级函数的所有功能；但在“形式化验证、跨链身份、逐门证明、组合语义”等架构属性上，DSU 不等价于门级函数。** FCT 因此保留双原语，而不是用 DSU 完全替代门级函数。

双原语策略使 FCT 能够同时服务两类需求：

- **极致安全与跨链身份**：门级函数。

- **高性能与 AI 原生**：DSU。

- **两者兼得**：混合模式。

## 4. 状态组件

### 4.1 计算容器

容器是 FCT 的核心状态单元。每个容器是一个链上智能合约账户，持有：

- **资产余额**：ETHER、稳定币、其他链资产；

- **DSU 引用**：该容器允许调用哪些执行单元；

- **FCT 函数引用**：该容器允许调用哪些门级链上函数；

- **私有状态**：以压缩状态承诺叶子形式存储；

- **管理权限**：容器 Owner，可转移；

- **AI 服务**：模型 CID、推理价格、收益地址。

容器不同于钱包：钱包属于人，容器属于那枚容器 NFT。容器的主人可以是人，也可以是 AI Agent。**转移容器 NFT，容器内的资产、模型服务、部署的网站、合约管理权以及仍在产生的收益，全部随之转移**。交易整个 AI 服务或链上业务，再也不需要信任任何中间人。

### 4.2 压缩状态承诺 CSC

FCT 不采用 LATCH 逐位存储，而采用**压缩状态承诺（Compressed State Commitment, CSC）**：

- **数据结构**：二进制 Merkle 树，哈希函数使用 Poseidon 或 Blake3。二进制树的分支比十六进制 MPT 短 4 倍，显著降低验证带宽。

- **热状态**：最近一个 epoch 内被访问过的容器，保留完整状态。

- **冷状态**：长期未访问的容器，状态被替换为状态承诺，完整数据由状态切片管理。存储节点仅保留预定义间隔的完整状态快照，中间状态通过历史交易重建。

- **验证**：任何冷状态可通过状态切片 + 向量承诺生成包含证明，无需信任任何链下数据提供者。

### 4.3 状态租金

容器为其占用的压缩状态承诺空间支付**持续租金**，按 epoch 收取。

- 租金定价由状态空间利用率动态调整。

- 不支付租金的容器，其状态被驱逐到冷存储，容器进入休眠，但仍可被唤醒。

- 这解决了“状态永久占用但无持续成本”的问题，防止状态无限膨胀。

### 4.4 跨链状态承诺

目标链状态根可锚定到 Ethercoin 清算层，Ethercoin 状态根可回锚目标链。跨链状态承诺使容器状态、函数执行结果、资产映射在目标链与 Ethercoin 之间可验证地同步。

## 5. 证明组件

### 5.1 执行证明

任何节点可以提交**执行证明**，证明它在给定输入下正确执行了某个 DSU 组合或 FCT 函数组合，并产生正确状态转换。执行证明可以是：

- **重放证明**：直接重放执行，适用于小计算量 DSU；

- **ZK 证明**：使用 STARK 或 SNARK 证明执行正确性，适用于大计算量 DSU；

- **TEE 证明**：硬件安全飞地生成远程认证，适用于隐私敏感任务。

### 5.2 证明市场

执行证明由**证明者（Prover）** 生成，验证者（Validator）只需验证证明，无需重放执行。这实现**计算与验证的解耦**——繁重计算在证明者侧完成，链上仅需低成本验证。

- 证明者通过提供证明获得 ETHER 奖励；

- 验证者通过验证证明获得手续费分成；

- 提交无效证明的证明者将被罚没保证金并永久失去资格。

### 5.3 最终性

一旦状态转换证明被超过 2/3 验证者确认，即达到最终性。证明验证是确定性的，最终性时间仅受证明生成与验证时间限制，预计达到**秒级**。

## 6. 清算组件

### 6.1 目标链适配器

Ethercoin 通过 FCT 在目标公链规划部署：

1. **目标链结算合约与轻客户端**：验证 Ethercoin 状态根与证明。

2. **FCT 计算与状态组件**：部署门级函数、DSU、容器、CSC。

3. **状态根锚定合约**：目标链状态根提交至 Ethercoin，Ethercoin 状态根回锚目标链。

4. **资产托管与映射合约**：目标链锁定资产，Ethercoin 清算层映射/铸造，提款时销毁并解锁。

5. **跨链消息与版税清算模块**：跨链函数调用、容器转移、版税结算。

### 6.2 清算流程

1. 用户在目标链锁定资产或提交状态转换。

2. 目标链 FCT 组件执行函数/DSU，生成证明。

3. 状态根与证明提交至 Ethercoin 清算层。

4. Ethercoin 验证证明，更新全局清算状态。

5. Ethercoin 上映射资产铸造/销毁，或触发目标链释放。

6. Ethercoin 状态根回锚目标链。

结果：Ethercoin 规划以目标公链的 L2/侧链形态运行，提供类似跨链桥的清算功能，但使用证明市场与容器状态，降低传统桥风险。

### 6.3 与跨链桥的区别

| 维度 | 传统跨链桥 | Ethercoin FCT 清算 |
| - | - | - |
| 信任假设 | 多签或外部验证者 | 证明市场 + 目标链轻客户端 |
| 状态验证 | 依赖桥方 | 状态根双向锚定 + 可验证证明 |
| 计算能力 | 仅资产转移 | 可验证计算 + 容器状态 + 资产 |
| 失败模式 | 单点故障、多签作恶 | 证明罚没、挑战期、限额、保险基金 |
| 代币 | 桥方代币 | ETHER 统一结算，FCT 无代币 |


### 6.4 安全机制

- **多证明**：TEE、ZK、Optimistic 三路径可选。

- **挑战期**：大额提款延迟与分批释放。

- **限额**：单笔与周期限额控制风险敞口。

- **保险基金**：协议金库部分资金用于极端情况赔付。

- **去中心化证明者**：无单一多签，防止单点作恶。

- **目标链重组防护**：轻客户端验证 + 多证明 + 挑战期，防止目标链重组导致清算错误。

以下均为规划，**不代表 FCT 链已激活或已主网运行**。

### 8.1 以太坊

- 规划部署身份锚定、函数 NFT 标准、状态根验证模板。

- Ethercoin 规划作为以太坊的 L2/侧链形态，提供计算与清算扩展。

### 8.2 Robinhood Chain

- 规划移植 EVM 合约：函数 NFT 合约、版税分配合约、结算合约验证逻辑。

- 适配约 100ms 出块，近实时状态更新。

- 优先费转化为创作者版税来源。

- 面向 RWA：股息计算函数、合规检查函数等可免信任组合。

### 8.3 Solana

- 规划将函数编译为 BPF 只读纯计算程序：只读账户、不执行 CPI、不标记可写。

- 状态由独立 PDA 与状态管理器更新。

- NAND 门网络编译为 Noir 电路，Groth16 证明通过 alt\_bn128 syscalls 验证。

- 通过 Rome Protocol 与 EVM 生态共享状态、原子调用。

- 函数 NFT 使用 Metaplex Core，版税插件适配。

- 利用 Sealevel 并行执行，释放免信任组合的并行价值。

### 8.4 其他公链

- Cosmos、Move 系、比特币 L2 等通过 FCT 适配器接入。

- 统一以 Ethercoin 为清算层，目标链为安全锚定源之一。

### 8.5 渐进式解耦

多链部署的关键风险控制原则是：每一步都不依赖前一步“完成”，而是**独立可验证**。

- 以太坊上的函数 NFT 在 Robinhood Chain 迁移之前就已经是有效的。

- Robinhood Chain 上的函数执行在 Solana 程序部署之前就已经可以独立运行。

- Solana 上的 BPF 纯计算程序和 Groth16 验证可独立于 Rome 桥接进行测试。

- Rome Protocol 集成失败不会使 Robinhood Chain 或以太坊上的成果作废。

- 某一步遇到技术障碍时，前一步成果不会作废。

## 10. 安全模型

### 10.1 执行安全

- 门级函数无副作用，免疫重入与状态操纵。

- DSU 只读，状态由容器层统一修改。

- 状态管理器守门：函数只提供“建议新状态”，状态管理器验证业务规则后写入。

- 证明市场：TEE、ZK、Optimistic 三路径可选。

- 无效证明罚没 ETHER 保证金。

### 10.2 状态安全

- 容器状态由 CSC 承诺，冷热分离。

- 状态租金防止状态无限膨胀。

- 跨链状态承诺双向锚定，防止状态不一致。

### 10.3 清算安全

- 多证明、挑战期、限额、保险基金、去中心化证明者。

- 目标链轻客户端验证 Ethercoin 状态根。

- 异常触发挑战与罚没。

- 无单一多签；大额提款延迟与分批释放。

### 10.4 防作弊矩阵

| 攻击类型 | 防御措施 | 技术实现 |
| - | - | - |
| Sybil 攻击 | 高质押 + 声誉积累 | 新节点任务配额 = f(质押, 声誉历史) |
| 虚假计算报告 | 分层验证 | 乐观锚点 / ZK 证明 / TEE 认证 |
| 模型冒名 | 权重哈希白名单 + 中间激活检查 | `modelCID` 必须在链上白名单；锚点检查捕获不同模型层输出分布 |
| 买卖合谋 | 随机验证者选择 + 验证者自身质押罚没 | VRF 选择验证者；验证者质押规模等于矿工 |
| 训练梯度伪造 | 检查点评估 + 优化器状态哈希 | 验证者运行测试集推理；无指标提升则罚没 |
| 蒸馏数据伪造 | 独立路径复现 + 代理签名 | 验证者通过不同代理路径获取答案，比较语义相似度 |
| 蒸馏代理篡改 | 路径签名 + 异常检测 | 每跳签名形成哈希链；验证结果差异超阈值则追溯并惩罚 |
| 矿工报价合谋 | VRF 随机选择矿工 | 报价历史上链，异常报价触发声誉惩罚 |
| 用户虚假高价锁定 | 任务创建锁定全额 ETHER | 挑战失败则罚没质押金 |
| 差额操纵 | 链上合约自动计算差额 | 参数由 DAO 治理，有上下界与时间延迟 |
| 跨链状态伪造 | 轻客户端 + 多证明 + 挑战期 | 目标链轻客户端验证 Ethercoin 状态根；异常触发挑战与罚没 |
| 跨链桥单点 | 去中心化证明者 + 限额 + 保险基金 | 无单一多签；大额提款延迟与分批释放 |


### 10.5 双原语安全边界

- **门级函数安全边界**：NAND + LATCH 纯逻辑，无副作用，物理上免疫重入与状态操纵。

- **DSU 安全边界**：只读执行，状态由容器层统一修改；需固定实现、精度与终止性。

- **混合模式安全边界**：DSU 输出由门级验证函数验证，状态管理器守门；证明链完整可追溯。

- **共享安全机制**：证明市场、挑战期、限额、保险基金、去中心化证明者。
